# 编辑与配图规范

## 语气学习

先运行 `style_profiles.py prepare`。缓存命中时只使用档案，不再读取样本。只有首次学习或指纹失效时才读取脚本返回的有限样本：

1. 首次学习时读取目标分类 3–8 篇代表作。
2. 增量刷新时只读取变化文章和最多两篇锚点文章。
3. 记录叙述人称、句长、段长、常用转场、技术细节密度、标题风格和结尾方式。
4. 将结果保存为紧凑语气档案；只迁移语言特征，不复制原句、具体经历或观点。

仓库既有文章通常以第一人称经验和技术解释为主。保留自然的中文表达，减少空泛的“赋能、抓手、闭环、底层逻辑”，避免连续的模板化排比和不必要的总结句。

## 从骨架扩写

- 把用户已给出的主题、判断和经历视为事实边界。
- 缺失的背景可补充通用解释；缺失的数据、时间、人物、公司内幕和实际效果必须询问或标注待确认。
- 技术内容给出适用条件、限制和失败场景。
- 删除重复段落和与主线无关的发散，不为了字数扩写。
- 保留代码、命令、表格、引用和链接的语义；无法确认的外链不要伪造。

## Markdown 结构

- `draft/polished.md` 不包含 front matter，也不重复文档标题。
- `#` 用作正文一级章节。每个一级章节下方 3 个非空行内放置章节图。
- 封面图片放在正文开头、第一个一级标题之前。
- 图片写成 `![准确的替代文本](https://...)`，替代文本描述信息而不是写“图片”。
- 代码块必须注明语言；命令和路径使用反引号。

## 图片创意

### 统一视觉

为一个项目先写 4–6 句视觉母题，包含色板、光线、镜头、材质、信息密度和禁止元素。所有图片复用母题，并针对章节改变主体。

### 封面 23:9

使用宽银幕构图，主体避开边缘，保留适度负空间。除非用户要求，避免在生成图中嵌入文字；模型生成的中文文字通常不可靠。
上传前由流水线校验实际像素比例；PNG/JPEG 允许 1% 误差。不符合时先使用图片编辑工具裁切，不能只在元数据中声明比例。

### 章节图 16:9

图片必须解释或隐喻该章节的核心关系，不能只用通用办公桌、握手、城市夜景。技术主题优先使用清晰架构隐喻、真实器材或编辑插画，不生成看似真实但错误的代码界面。
上传前同样校验实际像素比例，不能用 CSS 拉伸伪装。

### 小红书图片

每轮至少一张首图，推荐 3:4。首图标题短、结论明确；复杂文字排版应使用可控的 HTML/CSS、SVG 或设计工具完成，不让图片模型直接生成大量中文。

## 事实与版权

- 不伪造引用、调研、用户反馈或跑分。
- 生成视觉不得模仿在世艺术家的独特风格，不使用无授权商标和人物肖像。
- 原语雀图片迁移到图床时保留原有语义与说明。
